# 剧梦全产品拆解与观澜借鉴报告

研究日期：2026-10-07。对标对象仅为用户指定的 [剧梦（jzzm.duanju.com）](https://jzzm.duanju.com/homepage)，不混用同名平台。本文记录研究证据与取舍；观澜的实际实施状态见[升级执行状态](UPGRADE_STATUS.md)。

## 证据边界

- **实见**：在用户已登录的剧梦客户端查看首页、项目库、新建剧本项目表单、一个已有自由模式项目的要素与分镜页、美术与音乐资产库、提示词库、无限画布列表与已登录画布、AI 实验室、广场、人效统计和剧小梦对话界面；另核对了顶部任务队列、消息中心、帮助文档、用户反馈、侧栏展开／收起及画布保存状态。仅做阅读和打开预览，未新建项目、提交付费生成、上传文件、修改用户资料或删除数据。
- **未验证**：各创作模式从空项目到成片的实际成功率；付费任务的生成质量、速度与失败恢复；剧小梦实际操作项目的权限边界；协作邀请、版权授权与团队管理的完整规则；所有隐藏菜单和快捷键。任务队列当前为空，无法验证运行中／失败任务的操作；未修改画布，故未测自动保存触发频率、失败重试和跨端一致性。
- **判定规则**：入口可见≠能力已完成；历史结果可见≠本次生成实测成功；界面相近≠产品逻辑等价。

## 1. 产品定位与信息架构

剧梦围绕短剧制作组织为五层：

1. **开局层**：首页以“剧本模式、自由模式、小说原文模式、SRT 字幕转分镜模式”四个显性起点分流；项目库新建菜单另可见解说漫、一键直出。
2. **项目生产层**：项目内先管理要素，再到分镜视频；自由模式的分镜页内整合素材引用、模型参数、结果历史、预览和时间线。
3. **资产层**：美术资产库分 IP 演员、公共、团队、个人和收藏；音乐资产库独立，提示词库独立。
4. **实验层**：无限画布和 AI 实验室独立于线性项目流程；画布项目列表与工作流广场并列。
5. **运营层**：广场、人效统计、积分、团队角色和版权申请服务平台规模化生产。

主导思想是“按输入材料和交付方式选路径”，而非让所有用户进入同一个万能编辑器。对观澜最有价值的是创作状态在项目、资产、分镜、任务之间可追踪。

## 3. 真实路径与交互规律

### 主路径

首页选择输入模式 → 新建项目并设交付规格 → 提取、确认角色／场景／道具 → 在分镜页按集和镜头引用素材 → 选生成方式与模型 → 在同页查看任务与候选历史 → 引用合适结果到时间线 → 预览及导出。

这条路径的强点是“素材与结果围绕当前镜头”，不用每次跳去独立管理页。角色造型、场景和道具先作为项目要素出现，选定后又能同步到跨项目资产库；反向从总资产库取用则支持复用。

### 第二路径

全局无限画布 → 选择已有画布或预览工作流 → 从项目库、资产库或本地导入 → 在全幅空间组织文本与媒体节点 → 查看生成结果和任务状态。画布列表是独立入口，不被塞在分镜步骤里。

### 辅助路径

AI 实验室为“选择处理能力—提交任务—任务列表取结果”；提示词库为“按用途选择模板—查看说明—收藏／创建”；音乐库为“试听—确认来源—申请使用”。这些路径都有独立目的，适合从主制作流程中分离。

## 4. UI/UX 与可用性观察

**值得学习**：首页按输入物分流；分镜页保留素材、输入、结果、预览和时间线的邻近关系；项目内要素与总资产库之间有明确同步动作；历史候选保留“引用／克隆／重新编辑”；画布占据主要空间，工具条退到边缘；工作流先只读预览再复制；实验室跨工具共用任务表。

**不能照搬的瑕疵**：已见一个分镜提示词超过页面 5000 字上限，显示超限并禁用生成，长提示词缺少就地压缩或分段引导。某既有剧小梦回复称无法查询积分、猜测用户可去“钱包／积分明细”，但产品的人效统计页实际列有个人消耗明细；助手不能把不存在或未经验证的菜单当指引。新建剧本项目在第一步就给出多个模型与规格字段，对个人创作者可能造成参数负担。IP 演员榜单、团队资产和音乐申请是平台运营需求，不是观澜核心创作能力。

### 全局框架补查：状态、任务、求助与导航

| 项目／画布局部导航 | 项目制作页用返回、贡献要素、分镜视频替换全局大侧栏；画布页用文件菜单（返回首页、返回画布项目页、重命名等）配合悬浮节点轨和底部视口工具。 | 进入专注工作后缩减全局入口，保留当前任务所需的上下文切换。 | 逐镜与无限画布维持两条独立路径。局部导航只显示当前流程步骤；全局任务、消息、求助留在顶栏；退出路径保持清晰。 |

**本次观察暴露的注意点**：剧梦的“保存时间”目前只在已观察的画布页明确可见，不能直接声称所有制作页一致；队列为空，无法判断失败重试是否顺畅；消息浮层装入大量历史版本通知，观澜应避免把高频任务结果淹没在公告里；侧栏收起后仅有图标，观澜应补足可访问名称与悬停提示。这里提炼的是交互结构，不复制剧梦品牌视觉、图标或实现代码。

| P1 | 澜芯跨页上下文 | 有对话、指南及本机动作 | 明确当前项目／镜头／节点上下文；能查到的数据直接引用，查不到的说清边界 | 猜测菜单或编造账户数据 |

## 6. 下阶段升级前仍需核验

1. 以空白测试项目分别走通剧本、小说、SRT、自由模式的输入、失败、撤销和导出；本次只核到入口及已有自由项目。
2. 对画布逐类核实节点数据类型、连接约束、文件入参、生成中／失败／结果分支和重启恢复；本次没有调用付费任务。
3. 对剧小梦设计一个“可执行动作矩阵”：只读问答、读取项目、修改草稿、提交计费任务分级，逐条核实是否有确认与审计记录。
4. 核实音乐与图片资产的授权约束，避免把剧梦平台可用的内容误认为观澜开源包可再分发。
5. 用非付费测试任务核对资产／下载队列的筛选、任务行跳转与失败状态；再验证画布连续编辑时的保存中、成功时间、离开页面和保存失败恢复。当前报告不将这两部分判为已验证。

**核心产品结论**：剧梦最值得观澜学习的不是某个单独按钮，而是三条不同目的的路径：阶段式项目制作、自由画布探索、独立任务工具；三者通过统一资产、候选历史和任务状态相连。观澜升级应先补这些连接与真实执行能力，再决定增加哪些工具。
